# SQLite 与地图数据

整理日期：2026-11-03。原阶段：05 SQLite 与业务闭环、06 校园地图数据导入。

## 当前功能与数据流

应用首次运行会在 `data/campuspath.db` 初始化模拟地图。数据库被 Git 忽略，保存在本机，不会自动同步；删除它会删除本机数据。

1. `database/schema.sql` 建立地图、网格、地点和路线记录表，`database/store.py` 负责初始化和访问。
2. “模拟地图管理”维护地点；“模拟地图导航”编辑会话中的网格副本。点击“保存地图”才写入 SQLite；“重新加载已保存地图”会放弃当前会话中未保存的修改。
3. 搜索时，`save_route()` 保存当前网格、起终点、路径、扩展顺序和统计信息。回放滑块不会重复保存记录。
4. “模拟路线历史”显示查询时的快照；后来修改地图不会改变原有快照。历史时间以 UTC 保存和显示。

地点入口必须位于可通行格子。保存地图时会在事务内检查保存基线，避免用过期页面覆盖其他已保存的地图或地点。校园道路采集使用同一个数据库中的独立记录，不覆盖模拟地图，见 `note/校园地图与道路采集.md`。

## 导出与导入地图

“模拟地图管理”可下载当前地图 JSON 备份，或预览并确认导入其他网格地图。**备份只含地图和地点，不含历史路线。**导入会替换当前地图及地点，历史快照保留；建议替换前先下载备份。

示例仅用于说明格式，不代表真实校园：

```json
{
  "name": "示例地图（模拟）",
  "grid": [
    [0, 0, 1],
    [1, 0, 0]
  ],
  "places": {
    "示例入口A": [0, 0],
    "示例入口B": [1, 2]
  }
}
```

- `name` 是非空地图名称；`grid` 是非空矩形二维数组，整数 `0` 可通行、`1` 不可通行。
- `places` 中的 `[行, 列]` 从 0 开始，入口必须在地图范围内且可通行；地点可以为空，但无法选择地点导航。
- JSON 不允许重复字段，导入页面限制文件不超过 2 MB。

导入需勾选确认。如果预览后其他会话改变了地图名称、网格或地点，程序会拒绝覆盖；请重新加载并重新确认。写入在 SQLite 事务中完成，失败时不会留下部分导入。导入后，旧导航会话需要重新加载；历史记录保留原快照，不会把新地图名称当作旧查询的名称。

## 如何准备真实数据

先确认资料来源和使用权限，再逐一核实校园道路、围栏、校门和建筑入口，确定网格范围及尺寸。依据确认结果填写网格，将入口映射到可通行格子；导入后选取地点与现场逐段对照。图片、经纬度和路径点不会自动转换成网格；未经核实，不应宣称导入结果能用于实际导航。

数据库和页面检查使用临时数据，覆盖初始化、保存重启、地点规则、导入验证、事务回滚、过期冲突和历史快照。运行全部检查：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
```
