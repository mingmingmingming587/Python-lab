# CampusPath 校园地图与最短路径查询系统开发计划书

制定日期：2026 年 10 月 30 日

项目性质：Python 课程综合实验，三人协作

项目状态：已建立协作骨架，主要功能尚未实现

## 一、项目目标与范围

以河北燕郊的应急管理大学校园为原型，开发一个通过浏览器使用的校园地图与路线查询系统。第一阶段选择一块范围适中的校园区域，人工整理并核实建筑入口、道路及障碍物，建立可编辑、可保存的网格地图。用户可检索地点、选择起终点，系统通过自主实现的 A* 计算并展示路线、搜索过程和查询记录。

系统路线只反映录入地图中的信息，不能保证实时道路、施工和校门状态；在数据未经充分核实前，不应将其作为实际出行的可靠指引。

### 课程要求与项目选择

| 内容 | 任务书要求 | 本项目计划 |
| --- | --- | --- |
| 基础功能 | 图形展示可编辑网格、建筑入口和障碍物；选择起终点；保存加载地图、地点及查询记录；地点检索与历史路线查看 | 完整实现，包含数据校验、持久化和一条可演示流程 |
| 数据库 | 至少三张有业务关联的数据表，支持增删改查 | 使用 SQLite，计划设计地图、网格、地点、路线记录四张表 |
| A* | AI 提高项；要求按当前障碍物实际计算，展示路径、扩展节点数和搜索过程，处理不可达 | 纳入本项目第一版，自主实现并接入业务 |
| 移动方式 | 四方向、每步代价 1、曼哈顿距离为建议 | 采用该建议，便于实现、讲解和验证 |
| 界面 | Web 页面或桌面窗口，不能只有命令行 | 使用 Streamlit Web 页面；是否接受 Streamlit 由老师最终确认 |

实时定位、卫星底图、BFS 对比、自动播放和自动重规划不是第一版的完成前提，待核心功能验收后再评估。

## 二、技术方案与运行方式

| 部分 | 技术 | 作用 |
| --- | --- | --- |
| 开发语言 | Python | 界面、业务、数据库和算法 |
| Web 界面 | Streamlit | 表单、地图编辑、导航和记录页面 |
| 数据存储 | SQLite 与 Python `sqlite3` | 保存地图、地点和路线查询记录 |
| 地图展示 | Plotly | 绘制网格、障碍物、搜索节点和路线 |
| 路径搜索 | Python 标准库 `heapq` | 自主实现 A* 优先队列 |
| 协作 | Git 和 GitHub | 分支开发、审查和合并 |

第一版使用表格或明确的网格编辑控件维护障碍物，用下拉框或搜索选择地点，用滑块回放搜索过程。暂不要求拖拽绘图、连续动画或独立前端框架。Python 环境和启动命令以仓库 `README.md` 为准。

## 三、整体业务流程

1. 初始化数据库及经过核实的示例地图。
2. 地图维护者创建或选择地图，编辑可通行网格、障碍物和建筑入口，并保存。第一版不要求登录或权限系统。
3. 用户按名称查找地点，选择地图、起点和终点。
4. 系统读取当前保存的网格，检查输入后运行 A*。
5. 页面显示路径、步数、扩展节点数与搜索过程；不可达时提示当前网格中没有可行路线，不推断现实中的具体原因。
6. 系统保存查询结果，用户可查看历史记录；重启应用后记录仍可查询。

地图修改后重新查询必须使用当前地图，不能把预先写死的路线当作 A* 计算结果。历史记录需保留查询时的地图快照，避免误以为旧路线与当前地图完全一致。

## 四、校园地图与数据准备

1. 三人共同选择首个覆盖范围，优先保证区域内的道路和主要建筑入口可核实。
2. 使用允许使用的资料及现场观察，记录建筑、入口、道路、围栏和暂不可通行区域，标注来源、核实日期与待确认信息。
3. 将区域整理为规则网格：`0` 表示可通行，`1` 表示障碍物；地点指向可通行的入口格。明确地图范围、网格方向、行列数及每格代表的实际范围或注明仅作示意。
4. 检查各地点入口与道路是否连通；用几组已知路线现场核对，修正错误和遗漏。
5. 将可以公开分发的示例数据和初始化方式纳入仓库；不将本地数据库或 `local/` 参考资料提交。

`local/apk-analysis` 中的地点和交互仅供分析、核实与借鉴。该资料不自动提供可通行道路网；不直接复制其中的反编译代码、密钥或未经授权的数据。原始来源、地图服务许可和坐标系需要在使用前确认。

## 五、功能模块与三人分工

| 成员 | 模块 | 主要工作 | 阶段交付 |
| --- | --- | --- | --- |
| A | 地图管理与数据库 | 数据库初始化；地图、网格、地点的增删改查和校验；查询记录保存与读取；地图管理页面 | 可保存并重新加载的示例地图、地点和记录；数据接口说明 |
| B | 路径规划 | 定义搜索输入校验；自主实现 A*、路径回溯和扩展顺序；处理不可达；编写关键测试 | 独立运行的算法、统一结果和测试说明 |
| C | 导航与可视化 | Streamlit 页面；地点选择；Plotly 网格及路线展示；搜索过程滑块；历史记录页面；对接 A 和 B | 可操作的导航界面、搜索过程展示及完整流程 |
| 三人 | 整合与验收 | 校园数据核实、接口讨论、代码审查、集成测试、报告与演示 | 可复现的应用、实验报告和演示材料 |

职责是主要负责范围，不代表其他成员不参与测试和整合。跨模块修改或接口变化先沟通，避免最后由一个人承担全部整合工作。

## 六、数据与接口约定

详细约定以 `docs/collaboration.md` 为准；若开发中需要调整，由三人确认并同步更新。

- 网格：非空矩形 `list[list[int]]`；`0` 可通行，`1` 障碍物。
- 坐标：统一使用从 0 开始的 `(row, col)`，地点入口必须在网格范围内且可通行。
- 搜索：输入网格、起点和终点，输出 `PathResult`；记录 `found`、`path`、`path_length`、`visited_order`、`expanded_count` 和 `elapsed_ms`。
- 路径长度是移动步数；起终点相同为 0，不可达时 `found=False`、路径为空、长度为 `None`。非法输入应明确报错。
- 地图、网格、地点和路线记录通过地图 ID 关联。具体表结构及数据访问接口由 A 与 B、C 确认；页面通过数据接口读取和保存。
- 历史路线需保留查询时间、地图、起终点、算法、结果与统计信息；第一版在记录中保存查询时的网格和地点名称快照（例如 JSON），并展示这是历史状态。数据访问层在保存记录时一次性写入快照与结果，删除地图时保留历史或明确提示并由用户确认删除关联记录。

## 八、实施阶段

时间以课程实际截止日期和三人可投入时间为准；当前没有经确认的截止日期，因此不虚构日历安排。

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| 0：准备 | 确认老师对 Streamlit 的要求、校园范围、数据来源、分工与接口；同步分支 | 三人能启动骨架，对首张地图和接口达成一致 |
| 1：并行开发 | A 做地图和数据库；B 用小网格做 A*；C 用模拟数据做展示；三人核实校园数据 | 地图可保存加载；算法通过基本案例；界面可展示模拟路线 |
| 2：首次整合 | 将一张已核实的小区域地图接入 A* 与导航页面 | 用户能选择两个真实地点并得到由当前网格计算的路线 |
| 3：补全流程 | 地图编辑、异常处理、搜索过程、历史记录与重启持久化 | 至少一条完整业务闭环能重复演示 |
| 4：验收交付 | 实地核验、测试、修复、报告、运行说明和演示准备 | 课程要求逐项检查通过，三人可解释各自工作 |

每个阶段完成后共同检查结果，再进入下一阶段；B 和 C 可使用明确标注的模拟数据并行开发，整合时必须替换为实际模块数据。

## 九、验证与验收

- **地图和数据库**：创建、修改、删除与重新加载；检查无效尺寸、重复地点、越界坐标、障碍物上的入口；重启后数据仍在。
- **A***：验证直线路径、绕障碍、不可达、起终点相同、非法输入；在小型已知网格核对最短步数和扩展顺序。记录测试地图、起终点、预期和实际步数、扩展节点数及不可达结果；如报告运行时间，注明设备和测量条件。可用简单对照方法验证，不必把 BFS 作为第一版产品功能。
- **业务闭环**：编辑地图后重新搜索，确认结果随障碍物改变；保存查询、重启并查看历史记录；检查历史网格快照与查询时状态一致。
- **真实校园核实**：抽查地点名称、入口和几条路线；记录未核实路段及核实日期，不夸大地图准确性。
- **交付**：提供源代码、依赖清单、数据库初始化脚本和可分发示例数据、启动说明、数据库设计、测试记录、实验报告、成员分工和演示材料。

## 十、Git 协作

`main` 是默认分支和共同开发基线。三个功能分支分别为 `feature/map-management`、`feature/path-planning`、`feature/navigation-ui`。开始开发前同步最新 `main`；每完成一个可审查的功能提交到自己的分支，通过 Pull Request 请求其他成员检查后合并回 `main`。合并后同步基线并运行相关检查。

不得提交 `local/`、虚拟环境、缓存或本地 SQLite 数据库；提交前检查暂存文件。对公共接口的修改先沟通并更新协作约定。

## 十一、风险与待确认事项

| 事项 | 影响与处理 |
| --- | --- |
| Streamlit 是否满足老师的具体要求 | PDF 允许 Web 页面，列举 Flask/Django，未明确列出 Streamlit；尽早向老师确认 |
| 地图真实程度 | 只有地点坐标不能推断道路；先缩小范围、核对入口和通行条件，注明未核实区域 |
| 底图及参考资料许可 | 确认数据来源与分发权限；不将 APK 参考目录和未知权限数据上传 |
| 网格精度与工作量 | 格子太粗可能穿墙或漏掉道路，太细则录入和维护成本高；先用小范围试做并现场验证 |
| 历史路线与地图变化 | 保存查询时的网格快照，避免后续地图修改使历史结果失去上下文；明确删除地图时的记录处理方式 |
| 浏览器实时定位 | 非本期目标；将来需 HTTPS 或其他安全环境、用户授权、坐标转换及精度验证，不能保证准确落到道路上 |
| 团队时间与能力差异 | 先实现最小闭环，延期功能不阻塞基础验收；定期共同测试和整合 |
