# 校园地图与数据接口

当前 `experiment` 使用 `reference/campus-map-basemap.pdf` 作为底图，分类由独立 JSON 网格提供。当前行列坐标沿用 `experiment2` 合入的 180×90 网格；旧版三层地图的道路、建筑坐标和门的位置没有直接迁入。

## PDF 如何进入程序

当前底图为 `reference/campus-map-basemap.pdf`，来自用户提供的单页校园地图。网格在 PDF 页面坐标中的边界为 `(95.811462, 43.870117, 500.440125, 858.226929)`。程序渲染并裁切该区域，保留图面文字，再映射到 180×90 行列坐标。

首次检查得到建筑 2689 格、道路 2227 格、边界 793 格、未标注 10491 格；道路有 2223 格和 4 格两个连通区域。连通检查与 A* 都只允许上下左右邻接。没有为了消除断点而补画道路。

初始分类保存在 `reference/initial-grid.json`，数据提取自原三页 `reference/campus-map-integrated.pdf` 的第 2 页，并与第 3 页逐格核对。原 PDF 留作来源记录。运行时直接读取 JSON 网格，可关闭底图查看分类格子。

底图指纹 `background_hash` 与网格来源 `source_hash` 分别校验。`source_hash` 沿用原网格标识，以兼容已有数据库、建筑标记和导出的地图 JSON。更换底图时仍需重新校准裁切边界。导入 JSON 修改的是分类、地点和入口。

## 建筑标记不等于导航入口

用户要求建筑坐标点可以在建筑内部。名称与原始 PDF 文字交叉核对，坐标通过两图建筑轮廓对应后，再在新图逐项检查；不沿用旧版吸附道路的地点数据。`set_building_marker` 允许将标记放在建筑或道路格；只保存 `places` 和标记说明，不修改 `classes` 或通行网格。现已根据 PDF 图面补入 70 个建筑位置标记，数据位于 `reference/building-markers.json`；全部落在建筑格内。它们是图面坐标，尚未核实为实际入口。

标记放在建筑内部时，通行格仍为 `1`。建筑入口应单独录入道路格；未录入时，导航使用附近道路格作为临时接入点，并提示该接入点待核实。

## 数据结构与接口

- `classes` 是 180×90 分类网格：0 未标注、1 建筑、2 道路、3 边界。数据库把每个分类格存入 `map_cells`，加载时生成二维 `grid`：道路为 0，其余为 1。保存会校验两者一致。
- 地点、入口和路径坐标为 `(row, col)`。当前地图不包含天桥跨层连接；以后若需要跨层导航，须重新设计和核实数据。
- `places` 存储地点标记；`place_kinds` 区分建筑与场地。`entrances` 每个地点保存一条入口，沿用单元素列表格式兼容原 JSON。入口包含名称、坐标和启用状态。手工设置入口必须位于道路格，后续封路时仍保留入口记录。图面推定入口另有 `source="map_inferred"`，缺省来源为手工录入。
- `open_pdf_project()` 返回地图资料、服务、修订号和地图状态。`CampusMapService` 提供加载、保存与历史查询。保存时递增修订号，供版本显示和导航刷新使用。历史记录包含地图快照。
- `astar(grid, start, goal)` 返回路径、步数、扩展顺序等结果。`plan_named_route` 根据可用入口计算路线；没有已录入入口时，`access_points` 标记临时接入点。
- `set_grid_region(state, bounds, classification)` 同步修改分类与通行网格；`bounds` 为 `(起始行, 起始列, 结束行, 结束列)` 闭区间，先校验再修改。
- 地图选择与草稿编辑只更新会话状态。“保存地图”在事务中替换整张地图，多个会话编辑时以最后成功保存的内容为准。

## 当前边界

PDF 没有天桥与地面门的分层数据。当前采用二维 `grid`；旧版的北侧门开关不适用于新图坐标，因此暂不显示，天桥信息需要依据新图单独校准。

数据保存在 `data/campuspath-integrated.db`，与旧数据库分开。`database/campus_project.py` 仅保留实际使用的地图保存服务，不再依赖旧版模拟数据库。查询历史保存网格快照，编辑地图不会改写历史。

## 脚手架清理

旧版模拟与学习页面、旧图专用坐标转换、APK/OSM 显示及对应模拟数据服务已从本分支移除。核心 A* 保留独立 BFS 最短步数对照、不可达和边界检查。四个页面改为 navigation、map_management、route_history、road_review。旧版代码可在提交 `327c7b1` 中查看；旧版数据库已按用户要求删除。

## 二维格式与旧数据

当前地图、地点、入口及路线坐标统一为二维。首次打开原两表数据库时，程序将单层 `grids[0]` 和 `(0, row, col)` 转换为二维，把当前地图写入地图、网格、地点和入口表。路线记录迁入新表时保留原始快照，读取时再转换旧坐标。旧数据含多层或跨层连接时拒绝转换，事务会回滚。

## 建筑标记校对

`reference/building-markers.json` 保存 70 个命名建筑的行列及来源。名称来自原始 PDF 文字；通过共同建筑轮廓确定新旧图面的对应关系后，在新 PDF 图面逐项核对。大部分名称中心直接落在建筑格，少数文字位于轮廓外或建筑群空地，调整至对应建筑内部后人工核对。职工公寓为建筑群代表点；停车棚的新图分类不清晰，暂不迁到其他建筑。没有给无名称的建筑猜测命名。

建筑位置种子会校验是否落在初始分类对应区域。已存在的数据库按标记版本补入缺失名称，保留已有标记与网格编辑。入口由独立资料 `reference/place-entrances.json` 管理。

## 运动场与名称导航的录入过程

补入运动场（东）和运动场（西），标记分别位于 `(115,45)`、`(112,16)`，来源为 PDF 图面。它们是场地标记，允许位于未涂成道路的场地内部；不改变原图通行状态。地点总数为 72，其中建筑 70。

名称导航由 `algorithms/place_navigation.py` 将地点和入口分开处理。已维护入口时，使用该入口运行一次 A*。未维护入口时，提供明确标注待核实的临时最近道路格。入口停用或受阻时提示核对入口。建筑标记与道路接入坐标分别维护。

`entrances` 保存地点对应的入口名称、`point`、`enabled` 和可选 `source`；`place_kinds` 区分建筑与场地。保存历史时，快照中的 `route_query` 记录选用入口、来源及 temporary 标志。图面推定入口的 temporary 为 true，手工指定入口为 false。已有入口全部关闭或阻断时，提示核对入口。

`reference/place-entrances.json` 为 89 个地点各提供一个候选点。建筑优先使用建筑分类连通块相邻的主要道路格；没有相邻道路的建筑和场地使用最近主路参考格。每个候选都有来源和说明，全部按图面推定处理。初始地图加载种子，已有数据库按 `entrance_markers_version` 只为没有入口的地点补入当前仍可通行的候选。旧多入口数据库迁移和 JSON 导入均优先保留已启用且当前道路可通行的一条；已有查询快照完整保留。

## 补齐室外地点

进一步补入 17 个场地标记，累计 70 个建筑与 19 个场地，共 89 个地点。新增轮滑场、排球场、东/西篮球场、东北/东区/西区网球场、北运动场、拓展场地、安国园、问地园、听心园、思玄苑、桃李苑、天水湖、和合广场及学子林。方位后缀仅为区分图中同名地点，不认定为学校正式命名。

西区网球场在 PDF 分类图中被涂为黄色；本次只按图面登记场地位置，不改动该格的原分类，也不将其变成道路。场地标记允许位于非边界格，其位置类型不决定可通行性。

## 早期呈现方式

图面、分类、地点和搜索结果分别控制。聚焦视图只调整轴范围，不修改网格、地点或路径。当前默认显示和操作方式见下文。

## experiment 地图工作台

原 `experiment1.2` 已合入 `experiment`。本次参照 `experiment1.1` 的深绿顶部栏、米白背景和紧凑卡片，保留 Python、Streamlit、Plotly、SQLite 与现有 A*。界面逻辑集中在 `visualization/workspace.py`，样式为 `visualization/workspace.css`；`pages/` 下四个文件保留原来的访问地址。

左侧操作台在导航、地点、历史和维护间切换，右侧地图位置不变。视图选项和 25%～33% 宽度在会话内保留；控件临时键和业务状态分开存储，避免切换页面后丢失。仍按分类格、地点圆点和路线格分层显示，不增加道路矢量线。

地图点选使用 Plotly 原生选择事件。普通地点圆点带名称和坐标；编辑时增加可选择的格心散点层，用于回填地点、入口或网格坐标。热力图本身不承担点选。框选根据格心落入矩形范围确定闭区间。点击“设为建筑”等分类按钮时调用 `set_grid_region` 更新草稿，地图预览随即更新。

道路格、地点标记和入口共用草稿和编辑历史。每个会话保留最多 20 步，Ctrl+Z 后退，Ctrl+Y 前进。撤销后应用新修改会清空重做记录。“保存地图”一次写入草稿并清空编辑历史。路线记录继续读取查询时的完整快照。

分类使用单一 Heatmap，根据 `state["classes"]` 的当前值着色，初始和编辑后的格子颜色与透明度一致。开启底图时未标注格透明，选区只画边框。维护中的 JSON 导入使用现有的 `campuspath-integrated-1` 格式，校验网格来源标识、网格版本、180 × 90 分类矩阵、地点和入口，并根据分类重建通行网格。恢复初始地图使用 `reference/initial-grid.json` 和 `reference/building-markers.json`。导入和恢复各替换一次草稿。

未保存草稿在操作台中提示，导航继续读取已保存地图，历史读取当时的快照。维护页可选择道路连通区域，`review_cells` 将选中区域的行列列表传给图面，只进行高亮和视野定位。路线、选区和道路核查均是临时显示层，分类数据只在编辑时更新。

搜索播放使用 `st.fragment` 定时展示已计算的扩展顺序；支持暂停和手动拖动进度，不重新搜索、不重复保存查询历史。本次保留原生组件，没有引入新的前端框架；矩形框选代替连续涂抹，尚未实现拖动标记。

## 恢复地图文字

工作台初版把 PDF 底图和地点名称都默认关闭，造成地图只剩色块与圆点。现默认开启底图和地点名称；已有浏览器会话只重置一次显示预设，之后保留手动选择，不改动地图或地点数据。

默认“清晰浏览”使用较大的纵向图面，地图内容单独滚动，工具栏保持在外面；“图层与布局”中仍可选择“全校总览”。清晰浏览时滚轮用于上下查看，地图右上角工具可缩放。文字使用 12 像素深色字及白色描边，并尝试八个方向减少名称重叠；密集区域仍需缩放检查，不保证在全校总览中同时读清全部文字。

## 建筑入口图标

`visualization/pdf_map.py` 使用绿色实心方框表示手工入口，绿色空心方框表示图面候选，橙色菱形表示入口受阻，灰色空心方框表示停用。起点为深绿色，终点为紫色，图例显示对应颜色与形状。悬停显示所属地点、入口名称、来源、状态和坐标。历史地图使用查询时的入口快照。图面候选仍需核实。

## 地点搜索

导航的起点、终点和地点维护改用 Streamlit 可搜索下拉框。点击选择框后输入名称，候选项在下方显示，选中后加载对应地点；仍可使用地图点选和交换起终点。
